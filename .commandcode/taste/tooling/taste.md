# Tooling

- Manages Windows toolchain versions via scoop (temurin21-jdk) and explicitly points out that scoop can switch the default version (e.g. `scoop reset temurin21-jdk`) — prefers that over ad-hoc version juggling; in practice build/test commands still fall back to inline `JAVA_HOME` overrides (e.g. `set "JAVA_HOME=...\temurin21-jdk\current"`) when the default is wrong. Confidence: 0.8
- Prefers PowerShell over `cmd.exe` for shell work in this Windows environment: cmd has no heredoc and no `head`/`tail`, and `;` chaining inside cmd parsing breaks, making pipelines and multi-command quoting unreliable. Confidence: 0.65
- Expects known repository verification traps to be handled proactively: a new settings category must be added to the settings-search test's component map **and** its group assertion, `axolotl:i18n-check` reports a zh-CN string identical to its en-US counterpart as untranslated, and newly added Vue imports typically need `eslint <files> --fix` for import sorting, while scripts under `scripts/axolotl/` are covered by the repo's shared prettier config and must be prettier-formatted like their sibling scripts. Confidence: 0.7
- Git commits must be made with `--no-gpg-sign`: a global GPG signing configuration on the machine is broken and bare `git commit` hangs/fails on it, so it is always disabled explicitly. Confidence: 0.8
- Repository automation scripts have a consistent shape to match: `scripts/axolotl/*.mjs` as dependency-free Node ESM (only `node:` builtins, no shebang, tab indentation), with sibling `*.test.mjs` files run directly via `node` instead of being wired into a test runner. Confidence: 0.6
